## Findings in implemented behavior (priority order)

1. **High — removing a communication group does not stop already queued cross-session delivery.** The broker checks a shared group when creating an ask or tell ([`check_peer`](src/comms.rs#L388)), but [`send_response`](src/comms.rs#L495), [`ack`](src/comms.rs#L630), and [`AppState::settle_comms`](src/app.rs#L324) do not recheck it. For example, after A asks B, deleting their only shared group still lets B queue an answer to A; an ask queued before deletion can also be injected afterward. This breaks the explicit “no shared group → no cross-session data transfer” invariant. Test group revocation before first delivery and before response/ack, then enforce authorization at delivery and reply boundaries.

2. **High — broker injections are raw PTY keystrokes, with no safe paste framing or terminator removal.** [`Injection::render`](src/comms.rs#L47) interpolates caller-controlled `text` and `from`, then appends `\r`; [`inject_write`](src/session.rs#L634) sends those bytes directly. Newlines, carriage returns, terminal controls, and an embedded bracketed-paste terminator can alter the receiver's input stream or submit additional commands. The blueprint §4 requires removing embedded paste terminators, wrapping payloads in bracketed paste, and submitting after a short delay. Add negative tests for CR/LF/control bytes and paste terminators, and test an actual PTY delivery path.

3. **High — bounded queues and input sizes are not enforced end to end.** The main IPC queue ([`tui.rs`](src/tui.rs#L117)) and both PTY event queues ([`session.rs`](src/session.rs#L123)) use unbounded `mpsc::channel`; each PTY output chunk is copied into an event ([`pty.rs`](src/pty.rs#L332)). The 100-event drain limits work per tick, not queued memory. [`mcp-serve`](src/mcp.rs#L553) reads arbitrarily long stdio lines, [`hook-relay`](src/relay.rs#L175) reads all stdin without a cap, broker message text/conversations have no overall bounds ([`comms.rs`](src/comms.rs#L119)), and [`settle_comms`](src/app.rs#L345) drains every injection for each target in one tick. A flooding child or caller can grow memory and stall rendering despite the five-message pressure check. Add bounded ingress, backpressure/drop policy, total broker limits, and the still-open flood-cannot-starve-input gate.

4. **High — Safe-Only block patterns do not inspect file paths or most tool arguments.** [`Policy::decide`](src/policy.rs#L64) extracts only `command`/`cmd`; [`safe_only`](src/policy.rs#L88) matches regexes against `tool + command`. A `Read`, `Write`, or `Edit` request whose `file_path` matches a configured block regex is never blocked on that basis; `Read` then auto-allows as a safe tool. The cache key ([`policy.rs`](src/policy.rs#L115)) also collapses requests with the same tool/command but different paths or other arguments. Test a blocked file path and distinct arguments, then classify the complete raw policy input while keeping display escaping separate.

5. **High — PTY writes can block the single-owner TUI loop.** Human input and broker delivery call [`pane_write`](src/session.rs#L619) / [`inject_write`](src/session.rs#L634), which call [`PtyPane::write_all`](src/pty.rs#L205) synchronously under a mutex on the main thread. A slow or stopped child can hold the loop in `write_all`, preventing input, hook decisions, and redraw. The blueprint requires a serialized writer worker with bounded queue/waits. Test a non-reading PTY and confirm UI/event progress while its input buffer fills.

6. **Medium — skill installation overwrites user edits.** [`install_one_skills`](src/install.rs#L586) uses `std::fs::write` on each install; it neither compares the bundled content nor writes a `.new` sidecar for a modified file. The blueprint §12 explicitly requires preserving user edits during skill refresh. An ordinary reinstall can destroy a customized `SKILL.md`. Add a scratch-home test for modified content before changing this behavior.

7. **Medium — the configured prefix key is ignored.** Config loads/saves `prefix` ([`config.rs`](src/config.rs#L60)), but [`InputRouter::is_prefix`](src/input.rs#L315) hardcodes Ctrl-b, and the status line advertises Ctrl-b ([`app.rs`](src/app.rs#L167)). A valid non-default `prefix` setting changes neither dispatch nor help text. Add a configuration-driven input test and thread the parsed key into the router/chrome.

8. **Medium — session creation can fail without telling the user.** The dialog closes before spawn, and [`handle_dialog_key`](src/tui.rs#L351) ignores the `create_session` error. Agent launch is wrapped in `sh -c 'exec ...'` ([`app.rs`](src/app.rs#L293), [`pty.rs`](src/pty.rs#L154)), so a missing CLI often appears as a short-lived exited session instead of an actionable missing-binary error. The Phase 5 gate specifically calls for binary-missing errors. Keep the dialog/error surface open or surface a clear failure card; test a nonexistent binary.

9. **Medium — installer can leave Codex MCP without its required environment.** [`ensure_codex_mcp_env`](src/install.rs#L466) treats any existing `env_vars` line as complete, without checking for `FORGE_IPC_ENDPOINT` and `FORGE_RUN_ID`. If a user's stanza already lists unrelated variables, registration reports success but `mcp-serve` cannot route or authorize calls. Merge the two required variables while preserving existing values and comments; test the existing-list case.

10. **Medium — some untrusted chrome text bypasses display escaping.** PTY cells and sidebar details use `safe_text`, but [`session_bar_segments`](src/ui.rs#L229) inserts raw group/session names, [`GroupDialog::view`](src/groups.rs#L355) inserts raw names, and [`status_text`](src/app.rs#L136) inserts the raw active name/group. A bidi/invisible/control-bearing name can visually spoof those UI areas. Use the same display encoder at every render boundary and test hostile names.

11. **Medium — terminal setup can leave raw mode enabled on partial failure.** [`TerminalGuard::setup`](src/tui.rs#L33) enables raw mode before `execute!(EnterAlternateScreen, ...)`, but creates the guard only after that call succeeds. If `execute!` fails, `run` returns with no guard to restore raw mode. Establish the guard immediately after enabling raw mode or explicitly restore on every later setup error; test with a failing output backend where feasible.

12. **Medium — `mcp-serve` accepts invalid JSON-RPC and malformed JSON.** [`Scanner::value`](src/mcp.rs#L137) accepts invalid numbers such as `01`, and [`handle_line`](src/mcp.rs#L396) accepts missing `jsonrpc` and boolean IDs. A direct probe of `mcp-serve` returned successful `initialize` results for `{"id":1,"method":"initialize"}`, `{"jsonrpc":"2.0","id":true,"method":"initialize"}`, and a request containing `{"bad":01}`. This violates the blueprint's malformed-JSON-RPC negative gate and may desynchronize clients. Use a strict parser/validation at the protocol boundary, with bounded input lines.

13. **Medium — atomic-write durability failures are hidden.** [`write_staged`](src/fs_atomic.rs#L24) fsyncs the file but ignores failure to open/fsync the parent directory ([`fs_atomic.rs`](src/fs_atomic.rs#L47)). It can report success when the rename is not durably persisted, contrary to the blueprint's temp → fsync → rename → directory-fsync contract. Propagate directory-sync errors and cover the failure path.

14. **Medium — basic session lifecycle actions are not wired into the TUI.** [`SessionManager::kill`](src/session.rs#L433) and `remove` exist, but [`UserCommand`](src/input.rs#L11) and [`handle_key`](src/tui.rs#L268) expose no kill/delete/rename action. The user-visible blueprint §3 and the Phase 2 manual gate require killing one of two sessions. A user currently cannot close an individual session from Forge, and exited cards accumulate until quit. Lock the prefix map with tests, then wire kill/delete (and rename) into it.

15. **Low — current group color and UI semantics diverge from the locked contract.** The blueprint defines group colors 0–9, while [`group_palette`](src/ui.rs#L202) cycles over eight colors. Several chrome elements use direct `Color::Yellow` ([`ui.rs`](src/ui.rs#L245), [`ui.rs`](src/ui.rs#L451)) instead of the required semantic theme API. This will make theme switching inconsistent when added. Establish ten semantic group roles and use them consistently.

## Planned scope still absent

These are gaps against the intended product, not evidence that the in-progress phases were claimed complete. The plan currently marks Phase 3 as doing, Phase 4 as done, and Phases 5–8 as TODO; code has already started portions of Phase 5. The implemented MCP surface advertises **5 tools** ([`tool_defs`](src/mcp.rs#L348)) versus **50 Unix Forge tools** required by the bring-up scope after excluding seven memory tools. Missing families include file transfer, status/start/compact/message-user, timers, checklists/tasks, walkthrough, projects, whiteboard backend, visual, and supervised terminal execution. No `rusqlite` dependency or recovery/checkpoint service exists in the current manifest/source. Remote sessions, VCS, team builder, Claudling, and whiteboard asset serving are also not present. The UI currently has an agent tab plus a human terminal tab, rather than the blueprint's seven logical views. Startup ([`main.rs`](src/main.rs#L71)) does not repair registrations, refresh skills, onboard, or offer crash recovery. The intended Go clikan and React frontend are explicitly excluded from this bring-up and should remain excluded.

The plan's Phase 2.6 intentionally replaced the blueprint's multi-session grid with a focused-pane/session-bar layout; this is a product decision to reconcile, not a code defect. The plan also deliberately drops selection mode and telemetry reporting. The no-memory decision is reflected correctly in the current code. Fresh installations starting in YOLO mode are also intentional per the user, overriding the blueprint's Off default.
